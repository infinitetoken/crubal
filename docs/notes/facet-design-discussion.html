Facet design rules

From your note on the Unitizer ("Enums should ALL be bubble only. With an N indicator… Date pickers need to be able to pick date or year or month/year") and your three screenshots, plus a look at every facet on the live site. Part one is what is wrong today. Part two proposes one rule per facet type, each with a working example. Part three is what needs your decision.

1 · What is wrong today

The live dictionary has 196 facets: 65 text, 55 choice lists (enums), 37 modules, 23 measures, 18 yes/no, 6 images, 3 dates, 1 reference, 25 with no type set.

Two sources disagree on the typeThe dictionary says one type and a template's placement says another, so the screen guesses. 5 facets: videoCodec (text vs choice), discFormat (text vs choice), hdrFormats (text vs choice), aspectRatio (measure vs choice), included (yes/no vs choice).
A choice list with no choicesVideo Codec is placed as a choice list but has no values, only a rule that fills "MPEG-2" on DVDs. Nothing to draw as bubbles, so you saw an empty box.
Bubbles plus a text boxProduction Format draws its 14 bubbles and a text box under them, because it is set to allow additions. The box reads as a duplicate of the pick. 15 enums are set this way.
Enums draw three different waysBubbles, a dropdown, or a scored ladder, chosen by size and settings. You asked for bubbles only.
Dates are all-or-nothingEvery date is a full day picker. Release years and month/year dates are common on discs and games, and a day picker forces a made-up day.
25 facets have no typeThey fall back to a plain text box whatever they hold.

2 · One rule per type

The type comes from one place, the dictionary. A template placement can change only placement things (where it is collected, the photo frame, gates), never the type. Each rule below is what every facet of that type looks like, everywhere: the Unitizer, the Editor, the product page.

Choice list (enum) — bubbles only

  • Always bubbles. No dropdowns, no separate box under them.
  • An N indicator beside the name says how many may be picked: pick 1, pick up to 3, or pick any.
  • Pick 1: tapping another bubble moves the pick. Pick up to N: a further tap past N is refused with a shake and "up to 3".
  • Allow additions becomes a last bubble, ＋ Other…, which opens a one-line box only when tapped. The new value joins the list as a bubble.
  • Long lists (more than about 20) get a filter line above the bubbles, still bubbles.
  • A choice list with no values is refused in the dictionary until it has some.

Date — set how precise it is

  • Each date facet has a precision set in the dictionary: Year, Month and year, or Full date.
  • Or Any: the field shows a three-way switch and you pick how much you know, per product.
  • Stored as written: 1989, 1989-11 or 1989-12-01. Sorting and filters treat 1989 as the whole year.
  • Shown as written too: "1989", "Nov 1989", "Dec 1, 1989". No made-up days.
Release date any precision
Stored: 1989

Image — the same control everywhere

  • One row: the photos as tiles, then one camera tile, then ⋯ for a file or a link (built last round).
  • Every image facet draws this, Packaged Image and Contents Image alike. Contents was a text field in the dictionary; it is fixed.
  • The facet's photos are the product's stock photos. The unit's own photos stay in the unit's photo slots, which carry the same names.
  • Open question below: should a product's image facet and the unit photo slot be one thing?

3 · What needs your decision

A. One source for the typeShould the dictionary be the only place a facet's type is set, with templates unable to change it? The 5 disagreeing facets would then follow their dictionary entry, and I would list each one for you to confirm (Video Codec as a choice list needs its values written: MPEG-2, H.264, VC-1, HEVC, AV1…).
B. Enums: bubbles only, with an N indicatorAgree with the rule as drawn (pick 1 / up to N / any, "＋ Other…" as a bubble for lists that allow additions, a filter over very long lists)? Is "up to N" set in the dictionary per facet?
C. Date precisionShould precision be set per facet (Year, Month + year, Full date) with "Any" as the option that shows the switch? Which do you want for Release date, Theatrical release date and Launch date?
D. Image facets vs unit photo slotsToday a product's Packaged Image facet (stock photos) and a unit's Packaged photo slot (this copy) are separate, linked only by the Queue proposing unit photos for the product. Keep them separate, or make the product's image facet simply show its slot's accepted photos?
E. Scored choice listsA few enums are "scored" (each pick also gets a 0–10 grade, drawn as a ladder). Keep that as the one exception to bubbles-only, or draw it as bubbles with a small grade under each pick?
