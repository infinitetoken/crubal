CRUBAL 2: one small language for facets, values and the systems that use them

Adopted Oct 13, 2026 (decisions recorded below; built in lib/crubal, reference in docs/crubal/README.md). This pulls together the facet-design discussion, the facets v2.0 brief, and the language draft, plus schema.org, Wikidata, CRUBAL (2026), the Universal Commerce Protocol (UCP, Shopify and Google, Jan 11 2026), and the value math. The goal: easy to adopt, learn and write. Part one teaches it. Part two shows what it carries. Part three lists the gaps.

0Why a language, and the one rule

Facets today live in database rows, template settings and code, each with its own spelling of the same idea. A language gives people, imports, AI and outside systems one way to read and write all of it.

The one rule: everything is a key and a value. A product's data is key/value pairs (as CRUBAL always was). A facet's definition is key/value pairs about a key. A contract is key/value pairs about a system. Learn key: value and you can read every part of it. The symbols in level 3 are only a shorter way to write the same pairs.

Storage does not change. The database keeps its JSON documents; the language is what gets read, written, shown and sent. One reader and one printer convert between the two.

Level 1 · everyone

Writing data: four rules

  1. key: value, one per line.
  2. Indent two spaces to put things inside something.
  3. - starts another item in a list. A short list can go on one line with commas.
  4. // starts a comment.
product: P-4QX7                           // National Lampoon's Christmas Vacation [Blu-ray]
  title: "National Lampoon's Christmas Vacation"
  format: Blu-ray
  releaseDate: 1989-12-01
  runtime: 97min
  regionCode: A
  isFlipper: no
  studio: &wd:Q126399                       // Warner Bros., a Wikidata item
  cast:
    - person: &wd:Q311319
      character: Clark Griswold
    - person: &wd:Q232327
      character: Ellen Griswold
  theatricalReleaseDate: 1989-12-01 [region: US]
  videoCodec: _                             // known key, value still to find

unit: U-9KD2 of P-4QX7
  condition: VG
  included: case, disc
  price: $12.50

A value's shape suggests its type; the facet's definition decides. 1989 is a year under releaseDate and a number under discCount. If shape and definition disagree, the reader flags the line.

Level 2 · people who define facets

Writing a facet: the same pairs, about a key

facet: videoCodec
  label: Video codec
  type: choice
  values: MPEG-2, H.264, VC-1, HEVC, AV1
  pick: 1
  on: product
  combine: replace
  aliases: codec, "Video Format"
  same-as: schema:encodingFormat
  extends: OpticalDisc
  version: 2026-10-13

Conditions in when use six words only: is, in, has, not, and, or. Example: when: format is Blu-ray and not has hdrFormats.

Level 3 · shorthand, optional

The symbol method: one facet on one line

Every level 2 definition can be written as one line. The reader expands it to the same pairs; the printer can turn any definition back into a line. You never have to use it, and every mark has one meaning only.

// spelled out
facet: videoCodec
  type: choice
  values: MPEG-2, H.264, VC-1, HEVC, AV1
  pick: 1
  aliases: codec
  same-as: schema:encodingFormat
  extends: OpticalDisc
  version: 2026-10-13
// shorthand
videoCodec{MPEG-2|H.264|VC-1|HEVC|AV1} ~codec =schema:encodingFormat <OpticalDisc /2026-10-13

Read a line left to right

  1. Front: ! if required, unit. if it lives on the unit.
  2. The key.
  3. Type mark stuck to the key: what it holds.
  4. How many: nothing = one, *3 = up to three, * = any.
  5. Tails, each after a space: ~ alias, = same as, < extends, + combine, / version.

1IDs and versions

      
    
        
  • Every facet has a short ID (F-7KQ2) and a key (videoCodec) that never changes. The label is free to rename; old spellings become ~aliases.
    • 
        
  • Every choice value has an ID (V-2HDK). "16x9" and "Widescreen" are aliases of one value.
    • 
        
  • Every change to a definition is a new dated version (/2026-10-13, UCP's style). You edit a draft and press Publish; history keeps who, when and why.
    • 
        
  • Safe or breaking is worked out from the difference between two versions' lines: more values, a higher "pick", a looser precision are safe. Fewer values, a lower "pick", a new type, a new unit or a new combine rule are breaking and start a migration of stored values (the recast job that already exists).
    • 
        
  • Templates place facets and always use the current version. They never hold their own copy of the type, so the dictionary and templates cannot disagree again.
    • 
      

    


    

      
2Classes and influence

      
A class (template) is a list of facet lines that extends other classes. A class may only narrow what it inherits: fewer values, a lower "pick", a tighter precision. That makes influence traceable: for any value, the reader can say which class introduced the facet and which ones narrowed it.


facet: format  // the dictionary: everything format can ever be
  type: choice
  values: DVD, Blu-ray, 4K, HD-DVD, VHS, LaserDisc
  pick: any

class: OpticalDisc
  extends: VideoRelease
  facets:
    format{DVD|Blu-ray|4K|HD-DVD}            // narrows: no tape
    videoCodec{MPEG-2|H.264|VC-1|HEVC|AV1}
    unit.discCondition{NM|VG|G|F|P} +worst

// on a product, each value can be traced:
format: Blu-ray      // allowed by the dictionary, narrowed by OpticalDisc
videoCodec: VC-1     // introduced by OpticalDisc

    


    

      
3Combine rules: the math

      
Whenever two contributions meet (a second stamp, a disc inside a case, units rolling up to a product, two filters), the facet's combine rule decides. Contributions are additive, deductive or independent.

      

        
RuleKindMathExampleOrder matters?

        
          
joinadditiveset unionformat, cast, languagesno

          
sumadditivea + bweight of a set, total runtime, quantityno

          
bestadditivemax (or earliest)release date of a set (earliest)no

          
narrowdeductiveset intersectionallowed values down the class chainno

          
worstdeductivemin; "yes only if all are yes"condition of a set, sealedno

          
deductdeductivea − bprice after faultsno, while every deduction is a fixed amount

          
replaceindependentlast one winstitle, edition nameyes

          
keepindependentparts keep their owneach disc's own regionno

        
      

      
    
        
  • Order stops mattering for every rule except replace: stamping in any order, or twice, gives the same result. The system warns only where order can change the answer.
    • 
        
  • Rollups write themselves: a set from its discs, a product from its units, a container from its contents is the rule run over the parts.
    • 
        
  • Merges are safe: imports over hand edits, AI filling gaps and two people editing meet cleanly (the same math offline apps use to sync).
    • 
        
  • Independent facets multiply: 3 formats × 2 regions × 2 editions = 12 possible variants, and they can be counted one at a time for filters. Facets with a when are dependent and need counts taken together.
    • 
      

    


    

      
4Contracts and transport: N maps, not N²

      
Every system (a printer, Shippo, eBay, the pricer, a screen) declares one contract in the same language: what it needs, what it gives back, how its own fields map to facets, when it may run and who may run it. Systems never map to each other, only to facets, so ten systems need ten maps instead of up to forty-five bridges. Machinery (settings classes like rack slots and printers) is the same thing inside our own house.


contract: shippo:label
  version: 2026-10-01
  needs: shipFrom, shipTo, parcel.weight
  gives: trackingNumber, label, postage
  reads:                                    // their field: our facet
    address_from.street1: shipFrom.line1
    address_from.zip: shipFrom.zip
    weight: parcel.weight in oz             // converted from lb
  writes:
    trackingNumber: tracking_number
  when: order.status is paid
  who: seller

contract: Location                          // an object maps its own columns once
  stores:
    shipFrom.line1: location.line1
    shipFrom.zip: location.zip

contract: ebay:listing
  needs: !title$80, !format, !unit.condition, price
  reads:
    Title: title
    Format: format {DVD>"DVD" | Blu-ray>"Blu-ray" | 4K>"4K UHD Blu-ray"}
    ConditionID: unit.condition {NM>2750 | VG>4000 | G>5000}

      
    
        
  • reads fills their field from our facet, writes brings their result back, stores means the object keeps it in its own columns. The only new mark is > in a value map: "our value becomes theirs".
    • 
        
  • Checking is free: before a system runs, its needs against the item's facets says what is missing ("eBay needs Format").
    • 
        
  • The screen assembles itself: running a contract shows its needs, each with its facet's own control.
    • 
      

    


    

      
5UCP and the outside world

      
UCP (ucp.dev) is the published way stores and AI shopping agents talk. It already works the way contracts do: each side publishes what it supports, they keep the overlap, and every response says which versions were used. CRUBAL 2 borrows its rules and travels inside it.

      

        
UCP ruleIn CRUBAL 2

        
          
Names owned by a reversed domain (dev.ucp.shopping.checkout)Prefixes declared once, prefix: me = com.mediaencyclopedia; then me:videoCodec, ebay:Format, schema:name. Inside our own files the bare key is enough.

          
Date versions per capability/2026-10-13 per facet and per contract

          
extends for add-onsextends / < for classes and contracts

          
Negotiation: keep what both sides supportA contract's needs against what an item carries

          
Catalog: typed slots plus an untyped metadata bagOur facets go out as an add-on, me:shopping.catalog.facets extends dev.ucp.shopping.catalog, so outside agents get typed, versioned facets instead of a loose bag

        
      

      
schema.org and Wikidata stay linked through same-as, so the data Google reads can be generated from the facets.
